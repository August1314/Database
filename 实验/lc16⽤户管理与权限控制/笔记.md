# SQL Server 用户管理与权限控制实验笔记

## 实验目标
学习SQL Server中的用户管理、权限控制和视图的使用，理解如何通过视图实现细粒度的权限控制。

---

## 实验示例1：授予用户查询特定课程的权限

### 实验目的
让用户"李勇"具有查询课程号为10010课程的权限。通过创建视图和授权的方式实现。

### Step1: 在数据库School上创建用户"李勇"

#### 1.1 创建登录（Login）
使用系统存储过程 `sp_addlogin` 创建SQL Server登录：

```sql
EXEC sp_addlogin '李勇', '123456', 'school', 'English'
```

**参数说明**：
- `'李勇'`：登录名（用户名）
- `'123456'`：密码（passwd）
- `'school'`：默认数据库
- `'English'`：默认语言

**执行结果**：
- 命令已成功完成
- 创建了名为"李勇"的SQL Server登录

#### 1.2 授予数据库访问权限
使用系统存储过程 `sp_grantdbaccess` 授予用户在指定数据库中的访问权限：

```sql
USE school
GO
EXEC sp_grantdbaccess '李勇'
```

**说明**：
- `USE school`：切换到school数据库
- `sp_grantdbaccess`：将登录映射到数据库用户，授予数据库访问权限
- 执行后，用户"李勇"可以在school数据库中执行操作（需要相应的权限）

**执行结果**：
- 命令已成功完成
- 用户"李勇"已获得school数据库的访问权限

---

### Step2: 创建视图CS_View

#### 实验目的
在choices表上创建视图CS_View，筛选课程号为'10010'的记录。

#### 操作步骤
以sa身份登录数据库，新建查询，执行以下SQL语句：

```sql
USE School
GO
CREATE VIEW CS_View AS
SELECT * FROM choices
WHERE cid='10010'
```

**代码说明**：
- `USE School`：切换到School数据库
- `CREATE VIEW CS_View AS`：创建名为CS_View的视图
- `SELECT * FROM choices WHERE cid='10010'`：视图定义，筛选课程号为10010的选课记录

**执行结果**：
- 命令已成功完成
- 视图CS_View创建成功

**视图的作用**：
- 视图是基于一个或多个表的查询结果，提供了数据的逻辑视图
- 通过视图可以限制用户只能访问特定的数据（本例中只允许访问课程号为10010的记录）
- 视图可以隐藏底层表的结构，提供更安全的数据访问方式

---

### Step3: 授予视图SELECT权限

#### 实验目的
在视图CS_View上给用户"李勇"授予SELECT权限。

#### 操作步骤
以sa身份登录，执行以下SQL语句：

```sql
USE SCHOOL
GO
GRANT SELECT ON CS_VIEW
TO 李勇
```

**代码说明**：
- `USE SCHOOL`：切换到SCHOOL数据库
- `GRANT SELECT ON CS_VIEW`：授予对CS_VIEW视图的SELECT权限
- `TO 李勇`：将权限授予用户"李勇"

**执行结果**：
- 命令已成功完成
- 用户"李勇"已获得CS_VIEW视图的SELECT权限

**权限说明**：
- `GRANT SELECT`：授予查询权限，允许用户执行SELECT语句
- 用户"李勇"现在可以查询CS_View视图，但只能看到课程号为10010的选课记录
- 用户无法直接访问choices表，只能通过视图访问

## 实验示例2：授予列级UPDATE权限

### 实验目的
对视图上score属性列的UPDATE权限授予给用户"李勇"，可以修改学生的成绩，但不能对学生的基本信息（例如学号、选课号）进行修改。

### Step1: 授予列级UPDATE权限

#### 操作步骤
以sa身份登录，授予CS_View视图中score列的UPDATE权限给"李勇"：

```sql
USE school
GO
GRANT UPDATE ON dbo.[cs_view] ([score])
TO 李勇
```

**代码说明**：
- `USE school`：切换到school数据库
- `GRANT UPDATE ON dbo.[cs_view] ([score])`：授予对cs_view视图中score列的UPDATE权限
  - `dbo.[cs_view]`：指定视图的完整名称（架构.视图名）
  - `([score])`：指定可以更新的列，只允许更新score列
- `TO 李勇`：将权限授予用户"李勇"

**执行结果**：
- 命令已成功完成
- 用户"李勇"已获得CS_View视图中score列的UPDATE权限

**权限说明**：
- **列级权限**：可以只授予对特定列的UPDATE权限，而不是整个视图
- **安全性**：用户只能修改score列，无法修改其他列（如no、sid、tid、cid）
- **细粒度控制**：通过列级权限实现更精细的访问控制

---

### Step2: 验证UPDATE权限

#### 操作步骤
以"李勇"身份登录，对学号为500024940的学生的成绩进行修改，改为90分：

```sql
USE school
GO
UPDATE cs_view
SET score = 90
WHERE no = 500024940
```

**代码说明**：
- `UPDATE cs_view`：更新cs_view视图
- `SET score = 90`：将score列设置为90
- `WHERE no = 500024940`：筛选条件，只更新学号为500024940的记录

**执行结果**：
- 操作成功
- 学号为500024940的学生的成绩已更新为90分

**验证结果**：
- ✅ 用户"李勇"可以成功更新score列
- ✅ 只能更新score列，无法更新其他列（如no、sid、tid、cid）
- ✅ 列级权限控制生效

**尝试更新其他列（应该失败）**：
如果用户"李勇"尝试更新其他列，例如：
```sql
UPDATE cs_view
SET sid = '999999999'
WHERE no = 500024940
```
应该会失败，因为用户没有sid列的UPDATE权限。

## 实验示例3：查看错误日志

### 实验目的
学习如何查看SQL Server的错误日志，了解系统运行状态和错误信息。

### Step1: 访问错误日志

#### 操作步骤
1. 在SQL Server Management Studio (SSMS)中，展开"对象资源管理器"
2. 展开服务器节点
3. 展开"管理"（Management）文件夹
4. 展开"SQL Server 日志"（SQL Server Logs）

#### 日志文件说明
SQL Server中保留最近6个错误日志的档案：
- **当前**：当前正在使用的日志文件
- **存档编号1-6**：历史日志文件，按时间倒序排列

**示例日志文件**：
- 当前 - 2018/1/1 0:00:00
- 存档编号1 - 2017/12/22 0:00:00
- 存档编号2 - 2017/12/6 10:35:00
- 存档编号3 - 2017/11/5 0:01:00
- 存档编号4 - 2017/10/28 0:00:00
- 存档编号5 - 2017/10/20 13:08:00
- 存档编号6 - 2017/10/17 22:03:00

---

### Step2: 查看日志详细信息

#### 日志文件查看器
选择相应的存档后，可以在"日志文件查看器"中查看日志的详细信息。

#### 日志信息列
日志文件查看器显示以下信息：
- **日期**（Date）：日志记录的时间戳
- **源**（Source）：日志的来源（如spid22s、SQL Server等）
- **消息**（Message）：日志的详细内容

#### 常见错误消息
在"消息"列中查找以下关键字：
- **failed**：表示操作失败
- **problem**：表示存在问题
- **error**：表示错误

**常见错误示例**：

1. **登录失败**：
   ```
   Login failed for user 'USER1'. 
   原因:密码与所提供的登录名不匹配。
   [客户端: ...]
   错误:18456,严重性:14,状态:8。
   ```
   - 错误代码：18456
   - 原因：密码与登录名不匹配

2. **账户密码问题**：
   ```
   Login failed for user 'USER3'. 
   Reason: The password of the account must be...
   错误:18488,严重性:14,状态:1。
   ```
   - 错误代码：18488
   - 原因：账户密码必须符合策略要求

3. **信息性消息**：
   ```
   This instance of SQL Server has been using a process ID of 13008 
   since 2017/10/20 13:08:44 (local) 2017/10/20 5:08:44 (UTC). 
   This is an informational message only; no user action is required.
   ```
   - 这是信息性消息，不需要用户操作

#### 日志筛选和搜索
日志文件查看器提供以下功能：
- **加载日志**：重新加载日志文件
- **导出**：将日志导出到文件
- **刷新**：刷新日志内容
- **筛选**：根据条件筛选日志条目
- **搜索**：搜索特定的日志内容

## 关键概念总结

### 1. 用户管理

#### 登录（Login）vs 用户（User）
- **登录（Login）**：SQL Server级别的身份验证，用于连接到SQL Server实例
- **用户（User）**：数据库级别的身份标识，用于在数据库中执行操作

#### 创建登录和用户
```sql
-- 创建登录
EXEC sp_addlogin '登录名', '密码', '默认数据库', '默认语言'

-- 授予数据库访问权限（创建用户）
USE 数据库名
GO
EXEC sp_grantdbaccess '登录名'
```

### 2. 视图（View）

#### 视图的作用
- **数据安全**：限制用户只能访问特定的数据
- **简化查询**：隐藏复杂的查询逻辑
- **数据抽象**：隐藏底层表的结构
- **权限控制**：通过视图实现细粒度的权限管理

#### 创建视图
```sql
CREATE VIEW 视图名 AS
SELECT 列名
FROM 表名
WHERE 条件
```

### 3. 权限管理

#### 权限类型
- **SELECT**：查询权限，允许读取数据
- **UPDATE**：更新权限，允许修改数据
- **INSERT**：插入权限，允许添加数据
- **DELETE**：删除权限，允许删除数据

#### 授予权限
```sql
-- 授予表/视图级权限
GRANT 权限类型 ON 对象名 TO 用户名

-- 授予列级权限
GRANT 权限类型 ON 对象名 (列名) TO 用户名
```

#### 权限级别
- **对象级权限**：对整个表或视图的权限
- **列级权限**：对特定列的权限（更细粒度）

### 4. 错误日志

#### 日志的作用
- **问题诊断**：帮助识别和解决系统问题
- **安全审计**：记录登录失败等安全事件
- **性能监控**：了解系统运行状态
- **故障排查**：分析系统错误和异常

#### 日志查看
- 通过SSMS的"管理"→"SQL Server 日志"访问
- 可以查看当前日志和历史日志（最近6个）
- 使用筛选和搜索功能快速定位问题

## 实验总结

### 主要知识点

1. **用户管理流程**：
   - 创建登录（sp_addlogin）
   - 授予数据库访问权限（sp_grantdbaccess）
   - 授予对象权限（GRANT）

2. **视图的使用**：
   - 创建视图限制数据访问范围
   - 通过视图实现数据安全
   - 视图作为权限控制的中间层

3. **权限控制**：
   - 对象级权限（整个表/视图）
   - 列级权限（特定列）
   - 细粒度权限管理

4. **错误日志**：
   - 查看系统日志
   - 诊断问题
   - 安全审计

### 最佳实践

1. **最小权限原则**：只授予用户完成工作所需的最小权限
2. **使用视图**：通过视图限制数据访问，而不是直接授予表权限
3. **列级权限**：对于只需要更新特定列的场景，使用列级权限
4. **定期审查**：定期检查用户权限和日志，确保安全性
5. **错误监控**：定期查看错误日志，及时发现和解决问题

### 安全考虑

1. **密码策略**：使用强密码，符合SQL Server密码策略
2. **权限分离**：不同用户授予不同的权限，避免权限过度集中
3. **视图安全**：通过视图隐藏敏感数据，只暴露必要的信息
4. **审计日志**：保留错误日志，用于安全审计和问题追踪
